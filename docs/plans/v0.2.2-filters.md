# v0.2.2 필터 확장 + GUI/CLI 동등성 실행 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 메모리 맵·프로세스·모듈·스레드·탐지의 필터를 확장하고, CLI와 GUI가 **같은 필터 구현을 공유**하도록 만들어 기능 범위를 동일하게 유지한다. 작업 중 발견되는 오류·버그·결함도 함께 수정한다.

**Architecture:** 필터 조건을 `xmem-core`의 값 타입(`RegionFilter`/`ProcessFilter`/`ThreadFilter`/`FindingFilter` + `matches()`)으로 정의하고, CLI(clap 플래그)와 GUI(툴바 컨트롤)가 이 한 구현만 사용한다. 플래그와 컨트롤은 1:1 대응이며, 동등성은 공유 구현 + 테스트로 보장한다.

**Tech Stack:** Rust stable, clap 4, egui/eframe 0.36.2, serde, 기존 crate 구조(core → windows → memory/pe/forensics/detection → cli/gui).

**Spec:** `docs/architecture.md` §12(CLI 계약), `docs/gui-design.md`

## Global Constraints

- 지원 플랫폼: **Windows x64 단일**(사용자 결정). ARM64/Win10 대응은 범위 밖.
- **새 의존성 금지.** 기존 serde/clap/egui만 사용한다.
- CLI와 GUI는 **동일한 필터 집합**을 제공해야 한다(플래그 ↔ 컨트롤 1:1). 한쪽에만 있는 필터를 만들지 않는다.
- 필터 로직은 `xmem-core`에만 둔다(CLI/GUI 양쪽에 복제 금지).
- `--json` 출력 스키마는 바꾸지 않는다(필터 결과만 달라짐).
- 기본값은 **필터 없음(전체 표시)**. 위험한 동작 없음(read-only).
- unsafe는 `xmem-windows`에만.
- cargo 명령 전 `$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"`.
- 빌드/테스트 전 `Get-Process xmem-gui,xmem-target -ErrorAction SilentlyContinue | Stop-Process -Force`.
- 게이트: `cargo fmt --all -- --check`, `cargo check --workspace -q`, `cargo clippy -q --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- 커밋 prefix: feat/fix/refactor/test/docs/style/chore + 한국어 메시지. **push·릴리스는 사용자 허락 후에만.**

## Review Focus

1. `--outside-modules` / `pe_like_only`는 모듈 목록이 비어 있으면 **아무것도 매칭하지 않는다**(XMEM-003/002 규칙과 동일한 침묵 원칙) — 테스트로 고정.
2. 필터 조합(예: readable + private + range)에서 AND 의미가 일관되는지 — 조합 테스트.
3. 좁은 창(<900px)에서 모든 필터에 접근 가능해야 한다 — 필터 팝업 + 미러링.
4. `--prot` 디코딩이 Windows 보호 비트와 일치하는지(GUARD/NOCACHE 비트는 무시하고 하위 8비트만).
5. CLI 한글 열 정렬(전각 2칸 계산)로 PPID 등 열이 밀리지 않는지 — 단위 테스트.

**Interfaces (Produces — Task 1~3이 사용):**

```rust
pub enum ProtectionMask { Rwx, Rx, Rw, R, None }   // serde snake_case

pub struct RegionFilter {
    pub readable_only: bool, pub writable_only: bool, pub executable_only: bool,
    pub class: Option<RegionClass>, pub state: Option<MemoryState>,
    pub protection: Option<ProtectionMask>, pub heuristic: Option<Heuristic>,
    pub pe_like_only: bool, pub outside_modules_only: bool, pub mapped_only: bool,
    pub range: Option<(u64, u64)>, pub min_size: Option<u64>, pub max_size: Option<u64>,
}
impl Default for RegionFilter { /* 전부 false/None */ }
impl RegionFilter {
    pub fn matches(&self, region: &MemoryRegion, modules: &[ModuleInfo]) -> bool;
}

pub struct ProcessFilter {
    pub accessible_only: bool, pub name_contains: Option<String>, pub arch: Option<ProcessArch>,
    pub session: Option<u32>, pub user_contains: Option<String>,
    pub protected_only: bool, pub parent_pid: Option<u32>,
}
impl ProcessFilter { pub fn matches(&self, p: &ProcessInfo, accessible: bool) -> bool; }

pub struct ThreadFilter { pub with_start_only: bool, pub suspicious_only: bool, pub tid: Option<u32> }
impl ThreadFilter { pub fn matches(&self, t: &ThreadInfo) -> bool; }

pub struct FindingFilter { pub min_severity: Option<Severity>, pub min_confidence: Option<Confidence>, pub rule_id: Option<String> }
impl FindingFilter { pub fn matches(&self, f: &Finding) -> bool; }
pub fn severity_rank(s: Severity) -> u8;      // Info=0 … Critical=4
pub fn confidence_rank(c: Confidence) -> u8;  // Low=0, Medium=1, High=2
pub fn display_width(s: &str) -> usize;       // 전각 2, 그 외 1
pub fn pad_display(s: &str, width: usize) -> String; // 좌측 정렬 패딩
```

**Semantics:**
- bool 필터는 해당 필드가 true일 때만 조건 적용(AND).
- `protection`: 하위 8비트(`raw & 0xff`)를 디코딩해 `Rwx`(0x40|0x80), `Rx`(0x20), `Rw`(0x04|0x08), `R`(0x02), `None`(0x01·0x00)과 일치 비교.
- `pe_like_only` → `heuristics.contains(Heuristic::PrivateExecutablePeLike)`.
- `outside_modules_only` → `modules`가 비면 false; 아니면 어떤 모듈 범위에도 안 들어가는 영역만 true.
- `range` → 겹침(`base < end && base + size > start`, saturating).
- `suspicious_only` → `start_address.is_some() && start_module.is_none()`.
- `protected_only` → `xmem_core::guard::is_protected_name(&p.name)`.
- `display_width`/`pad_display`: CJK 전각(0x1100-0x115F, 0x2E80-0xA4CF, 0xAC00-0xD7A3, 0xF900-0xFAFF, 0xFE30-0xFE4F, 0xFF00-0xFF60, 0xFFE0-0xFFE6) = 2칸.

### Task 1: CLI 플래그 (core 필터 사용)

**Files:** `crates/xmem-cli/src/cli.rs`(Args 구조체), `commands/{memory,process,modules,threads,detect,snapshot}.rs`

| 명령 | 추가 플래그 |
|---|---|
| `memory map` | `--readable-only --writable-only --executable-only --state commit\|reserve\|free --class image\|mapped\|private --prot rwx\|r-x\|rw-\|r--\|--- --heuristic exec-private\|exec-anon\|pe-like\|wx --pe-like --outside-modules --mapped-only --range START:END --min-size N --max-size N --sort addr\|addr-desc\|size-desc` |
| `process list` | `--name SUBSTR --arch x64\|x86 --session N --user SUBSTR --protected --ppid N` (+기존 `--accessible-only`) |
| `modules` | `--filter SUBSTR --arch x64\|x86 --unparsed` |
| `threads` | `--with-start --suspicious --tid N` |
| `detect` | `--min-severity info\|low\|medium\|high\|critical --min-confidence low\|medium\|high --rule XMEM-003 --sort severity\|address\|rule` |
| `snapshot diff` | `--only regions,content,modules,threads,detections` (콤마 목록, 비면 전체) |

- `--range`는 기존 `memory scan`과 동일 형식(`START:END`, 0x 접두 hex 허용). 기존 `parse_range` 재사용.
- `modules --arch`/`threads`/`detect` 필터는 **수집 후** 적용(추가 API 호출 없음).
- `memory map` 정렬은 기존 GUI `MapSort`와 동일 순서(addr/addr-desc/size-desc).
