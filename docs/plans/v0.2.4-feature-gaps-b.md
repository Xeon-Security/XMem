# XMem v0.2.4 Batch B 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기능 갭 Batch B 6건(⑥ 스캔 진행률 · ⑯ 덤프 진행률 · ⑭ 해시 예산 옵션 · ④ 위험도 스코어 · ⑫ 언로드 모듈 탐지 · ⑱ 실험 확장·추세)을 CLI·GUI·코어에 구현하고 v0.2.4로 릴리스한다.

**Architecture:** 새 로직은 각 crate의 기존 책임 경계를 따른다 — 스캔 진행률·언로드 모듈 후보는 `xmem-memory`, 덤프 진행률 콜백은 `xmem-windows`, 위험도 스코어는 `xmem-detection`, 실험 이력은 `xmem-experiments`, 해시 예산은 기존 `xmem-forensics::CollectOptions` 재사용. CLI/GUI는 플래그·표시만 담당하고 로직을 창작하지 않는다.

**Tech Stack:** Rust stable(1.98), windows-rs 0.62(기존 features), rayon(기존), serde/serde_json(기존), eframe/egui 0.36.2(기존). **신규 의존성 없음.**

**Spec:** `docs/future-work.md` §2(기능 갭)의 ⑥⑯⑭④⑫⑱, 이전 릴리스 관례(`docs/plans/v0.2.0-feature-gaps-a.md`, `v0.2.2-filters.md`).

## Global Constraints

- 지원 플랫폼: **Windows 10/11 x64 단일**. 다른 아키텍처/OS 대응 금지.
- **새 의존성 추가 금지** — 표준 라이브러리와 기존 crate만 사용.
- `unsafe`는 `xmem-windows`에서만. workspace lint(`unsafe_code=deny`, `clippy unwrap_used/expect_used=warn`)를 클린 유지. 런타임 경로 `unwrap()/expect()` 금지(테스트는 `#![cfg_attr(test, allow(...))]`).
- Read-only 기본: 분석 명령은 대상 프로세스를 변경하지 않는다. 실험은 XMem이 spawn한 `xmem-target` 한정(기존 유지).
- 게이트(각 Task 완료 시, 실패하면 다음 Task 금지): `cargo fmt --all` → `cargo check --workspace -q` → `cargo clippy -q --workspace --all-targets -- -D warnings` → `cargo test -q --workspace`.
- 커밋 prefix(feat/fix/docs/style/test/chore) + 한국어 메시지. **push는 Task 7(릴리스)에서만.**
- **GUI 창 실행 금지**(사용자 요청): 검증은 `cargo build -p xmem-gui`와 테스트만. 화면 확인은 사용자에게 요청.
- 빌드 전 `Get-Process xmem-gui,xmem-target -ErrorAction SilentlyContinue | Stop-Process -Force`(exe 잠김 os error 5).
- cargo 명령 전 `$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"`. red 확인은 `cargo check -p <crate> --tests`(cargo check는 `#[cfg(test)]`를 컴파일하지 않음).
- JSON envelope 스키마(`{ok, schema_version, data}`)와 기존 키는 유지하고 **필드 추가만** 허용.

## Review Focus

1. **진행률 콜백의 성능**: 영역이 수십만 개일 때 콜백이 O(n) 이상 부르면 안 된다 — 스로틀(CLI 10% 단위, GUI는 원자 카운터 폴링)을 지킨다. 테스트: 진행도 카운터가 total과 정확히 일치.
2. **덤프 콜백 방어성**: `MiniDumpWriteDump` 콜백은 Windows가 직접 호출하므로 절대 패닉하면 안 된다(모든 포인터 접근은 방어적, 실패는 무시하고 계속, 항상 `TRUE` 반환). 테스트: 진행도 콜백이 있는 경로로 자기 덤프가 성공하고 bytes_written > 0.
3. **해시 예산 입력 경계**: `--hash-budget 0`·`--hash-all`·`--hash-budget` 동시 지정·잘못된 접미사 처리. 테스트: 0 → 오류, 잘못된 값 → 오류, `--hash-all` → `u64::MAX`.
4. **위험도 스코어 결정성**: 같은 findings → 같은 점수, 0건 → score 0/level None. 테스트: 빈 findings·단일 Low·혼합 케이스 값 고정.
5. **이력 로그 견고성**: `experiments.jsonl`이 없거나 손상된 줄이 섞여도 로드가 실패하지 않는다(손상 줄 건너뜀). 테스트: 손상 줄 포함 파일 로드.
