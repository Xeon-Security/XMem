## Global Constraints

- 지원 플랫폼: **Windows x64 단일** (사용자 결정). Win10/ARM64 대응은 스코프 외.
- 새 의존성 추가 금지. 규칙/억제 파일은 JSON(serde_json) 사용, MemoryImage는 별도 `.xmemimg` 파일(Batch C).
- `unsafe`는 `xmem-windows`에만. workspace lint: `unsafe_code=deny`, clippy `unwrap_used/expect_used=warn`(테스트는 `#![cfg_attr(test, allow(...))]`).
- 런타임 경로 `unwrap()/expect()` 금지. 오류는 `XmemError` variant + context.
- read-only 기본. 실험은 XMem이 spawn한 lab target 한정.
- 모든 cargo 명령 전 `$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"`.
- 빌드 전 실행 중인 `xmem-gui`/`xmem-target` 강제 종료(exe 잠김 → os error 5).
- 게이트: `cargo fmt --all -- --check` / `cargo check --workspace` / `cargo clippy -q --workspace --all-targets -- -D warnings` / `cargo test --workspace`.
- 커밋 메시지 prefix: feat/fix/docs/style/refactor/test/chore + 한국어.
- 문서는 한국어. 계획서 체크박스는 완료 시 `[x]`로 갱신.

## Review Focus

1. **경로 변환 정확성**: 여러 볼륨(C:, D:)·드라이브 문자 없는 경로(`\Device\...` 그대로)·대소문자 혼용에서 변환이 틀리지 않고, 변환 실패 시 원본을 유지해야 한다.
2. **WOW64 혼합 프로세스의 arch**: 32비트 모듈과 64비트 모듈이 섞인 프로세스에서 모듈별 arch가 각각 맞게 나오고, PE 읽기 실패 시 프로세스 arch로 폴백해야 한다.
3. **좁은 창에서의 표 접근성**: 창을 최소 폭(820px)까지 줄여도 세로 스크롤바·행 클릭·선택이 정상 동작해야 한다.
4. **취소의 실제 동작**: 취소 버튼이 눌린 뒤 백그라운드 작업이 실제로 멈추거나(취소 토큰 경로) 최소한 결과가 적용되지 않아야 하고, `Cancelled` 상태가 오류 배너로 보이면 안 된다.
5. **내보내기 무결성**: 내보낸 JSON/CSV가 원본 결과와 일치하고(라운드트립), 파일 쓰기 실패 시 임시 파일이 남지 않아야 한다.

```rust
/// `\Device\HarddiskVolumeN\...` → `C:\...` (볼륨 문자를 찾지 못하면 원본 유지)
pub fn normalize_device_path(path: &str) -> String {
    for letter in b'A'..=b'Z' {
        let drive = format!("{}:", letter as char);
        let Some(device) = query_dos_device(&drive) else { continue };
        if path.len() >= device.len() && path[..device.len()].eq_ignore_ascii_case(&device) {
            let rest = &path[device.len()..];
            return format!("{drive}{rest}");
        }
    }
    path.to_string()
}
```

`query_dos_device(drive: &str) -> Option<String>`는 `QueryDosDeviceW`를 1024 u16 버퍼로 호출해 `utf16_z_to_string`.
`mapped_file_name`이 `normalize_device_path(&name)`을 적용하도록 수정.
